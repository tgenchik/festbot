# festbot — бот розыгрышей для MAX

Go, PostgreSQL (pgx + goose), Redis (asynq), официальный клиент MAX Bot API.

## Процессы

| Бинарник | Что делает |
|---|---|
| `cmd/bot` | Принимает апдейты MAX (вебхук в проде, long polling локально), показывает экраны, выдает промокоды, проверяет подписку, регистрирует заявки, ведет анкету победителя |
| `cmd/worker` | Очереди asynq: рассылки, уведомления победителям, дедлайны призов; планировщик ежедневного розыгрыша; outbox relay |
| `cmd/admin` | HTTP API для команды: партнеры, расписание, загрузка промокодов, розыгрыши с подтверждением, CSV-выгрузки, рассылки, статистика |
| `cmd/migrate` | Миграции goose (`up`, `down`, `status`) |

## Пакеты

```
internal/
  campaign/      расписание: какой партнер в какой день
  promo/         пул кодов и атомарная выдача (SKIP LOCKED + advisory lock на пользователя)
  entries/       заявки на розыгрыш дня, активные дни = шансы в финале
  subscription/  проверка подписки через GET /chats/{id}/members
  draws/         ежедневный и финальный розыгрыш (взвешенный выбор без повторов, seed хранится)
  prizes/        анкета победителя, согласие, передача приза резервисту
  broadcast/     рассылки и общий лимит скорости в Redis
  outbox/        надежная постановка задач в Redis из транзакций Postgres
  texts/         все тексты и кнопки бота в одном месте
  messenger/     обертка над MAX Bot API
  stats/         метрики из раздела 8 ТЗ
```

## Ключевые решения

**Шансы.** Таблица `active_days` с ключом (пользователь, день). Промокод и заявка в один день пишут одну и ту же строку, поэтому правило «один день = один шанс» выполняется на уровне БД. Потолок 10 применяется при подсчете.

**Промокоды.** Свободный код берется через `FOR UPDATE SKIP LOCKED`, так что параллельные запросы разных людей не ждут друг друга и не получают один код. Двойной клик одного пользователя сериализуется `pg_advisory_xact_lock`, второй запрос получает тот же код.

**Розыгрыши.** Итоги сохраняются черновиком (`draft`) вместе со снимком участников и seed генератора ChaCha8. Уведомления уходят только после `POST /api/draws/{id}/confirm`. По seed и снимку результат можно воспроизвести. Уникальные индексы не дают провести два розыгрыша за один день или два финала.

**Redis + outbox.** Постановка задачи в Redis не входит в транзакцию Postgres, поэтому критичные задачи (уведомить победителей, передать приз резервисту) сначала пишутся в таблицу `outbox` в той же транзакции, а relay в воркере переносит их в asynq с `TaskID = outbox-<id>` — повтор не создаст дубль.

**Финальный розыгрыш.** Сейчас реализовано как `FINAL_WINNERS` основных победителей (по умолчанию 5, приз — 2 билета каждому) и `FINAL_RESERVES` резервных. Если основной победитель не заполнил анкету за `CLAIM_TTL` или отказался дать согласие, приз переходит следующему резервисту по порядку.

## Режим разработки без MAX

Бота в MAX можно создать только на верифицированный профиль организации, ИП или самозанятого. Пока токена нет, ставьте `DEV_MODE=true` (так в `.env.example` по умолчанию): вместо MAX бот откроет локальный чат на http://localhost:8080.

В этом чате можно писать от имени нескольких тестовых участников, отмечать подписку на канал партнера галочкой и запускать сценарий кнопками: завести партнера на сегодня, разыграть призы дня, разыграть главный приз, стереть все данные. Действия проходят через тот же `bot.Handle`, что и в проде, а сообщения воркера (уведомления победителям, рассылки) тоже приходят в этот чат через Redis. Без MAX остаются непроверенными только отправка через его API и реальная проверка подписки.

## Запуск

```bash
cp .env.example .env      # вписать ADMIN_PASSWORD; BOT_TOKEN нужен только при DEV_MODE=false
go mod tidy               # создаст go.sum
make up                   # postgres, redis, миграции, bot, worker, admin, asynqmon
```

Локально без вебхука бот работает через long polling (оставьте `WEBHOOK_URL` пустым). Мониторинг очередей — http://localhost:8082.

Тесты: `make test` (алгоритм розыгрыша), `make test-integration` (сквозной сценарий на Postgres: конкурентная выдача кодов, заявки, шансы, розыгрыши, анкеты и резервисты, статистика).

## Admin API (Basic Auth)

```bash
A="-u admin:$ADMIN_PASSWORD http://localhost:8081"

# партнер и его день
curl -X POST $A/api/partners -d '{"name":"Партнер","channel_id":-123,"channel_url":"https://max.ru/partner","promo_where":"на сайте partner.ru","promo_valid_until":"2026-12-31T00:00:00Z"}'
curl -X PUT  $A/api/days -d '{"date":"2026-11-01","partner_id":1,"winners_count":3,"prize_title":"мерч","prize_instruction":"Мы напишем тебе в течение 3 дней."}'

# промокоды: по одному в строке
curl -X POST $A/api/partners/1/promocodes --data-binary @codes.txt

# розыгрыши: дневной запускается сам ночью, можно и вручную
curl -X POST $A/api/draws/daily/2026-11-01
curl $A/api/draws/1
curl -X POST $A/api/draws/1/confirm
curl $A/api/draws/1/participants.csv -o draw-1.csv

curl -X POST $A/api/draws/final
curl $A/api/draws/2/claims.csv -o claims.csv

curl -X POST $A/api/broadcasts -d '{"text":"Сегодня на сцене новый партнер!"}'
curl $A/api/stats
```

## Что проверить до запуска

1. Бот должен быть администратором канала каждого партнера — без этого `GET /chats/{id}/members` не вернет участников. Проверить на реальном канале в первую очередь.
2. Коды ошибок MAX для заблокировавших бота пользователей (`messenger.IsUnreachable`) и лимиты на отправку — сверить с документацией и подобрать `SEND_RATE_PER_SEC`.
3. Трактовку финального приза («10 билетов, 5 победителей по два») и срок ответа победителя согласовать с заказчиком и правилами акции.
4. Текст согласия на обработку и передачу персональных данных должен пройти юристов (152-ФЗ).
5. Веб-интерфейс админки поверх API пока не сделан.
